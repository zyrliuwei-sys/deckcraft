<h2 id="choose">应该下载哪个 DeckCraft 文件？</h2>

选择下载包之前，先确认三个条件：操作系统、处理器架构，以及希望安装到系统还是使用便携版。发布页面可能同时列出图形应用、命令行工具、浏览器包和源代码。如果只看到文件名里有 DeckCraft 就点击，很容易得到一个真实但不适合当前电脑的文件。

想快速找到入口，可以打开[本站下载页](/download)。想获取上游当前版本，应使用[官方 GitHub 最新发布页](https://github.com/storytold/deckcraft/releases/latest)。本站快捷下载面板可能仍指向较早的已测试版本，固定版本并不等同于最新版本；在线编辑器也与桌面安装包分开维护。

建议按下面顺序判断：

1. **操作系统：**区分 Windows、macOS，以及 Linux 对应发行版的包格式。
2. **处理器架构：**x64/x86_64 与 ARM64/aarch64 不是同一类构建。查看电脑系统信息，不要只根据品牌猜测。
3. **安装方式：**安装器负责常规系统集成，便携压缩包需要完整解压，Linux 包通常交给相应包管理工具。
4. **程序类型：**文件名含 `cli` 通常表示命令行工具；“Source code”是供开发者编译的源码，不是普通安装器。

如果只是想体验几页幻灯片，可以先打开[在线编辑器](/app)。[浏览器指南](/guides/deckcraft-online-guide)会说明使用条件和保存方法。先通过小型练习了解编辑方式，再决定是否安装桌面版，往往更容易发现自己的实际需要。

<h2 id="source">找到发布版本并核对下载文件</h2>

下载来源应是 `storytold/deckcraft` 仓库的发布页面。选择文件前，阅读版本标题、说明和完整附件列表。本指南核实时，上游列出的最新版本为 v0.15.1；后续版本请以实时页面为准。旧文章或截图里的版本号不应成为长期固定推荐。[查看上游发布记录](https://github.com/storytold/deckcraft/releases)。

第一次测试完成之前，保留安装包和对应版本信息。可以简单记录版本号、系统、架构和下载日期。这样既方便反馈问题，也能避免下载目录里积累多个安装器后，不知道自己实际运行的是哪一个。

发布附件中提供 `SHA256SUMS.txt`，用于核对下载文件的字节内容。比较时必须使用同一个版本、同一个文件名对应的校验值。其他系统或架构的文件本来就应该有不同的值。校验匹配说明文件与清单一致，不是对应用所有行为的全面保证。

下面是计算本地 SHA-256 的示例，执行前把示例文件名替换成实际下载名称：

```powershell
# Windows PowerShell
Get-FileHash .\downloaded-deckcraft.msi -Algorithm SHA256
```

```bash
# macOS
shasum -a 256 downloaded-deckcraft.dmg

# Linux
sha256sum downloaded-deckcraft.AppImage
```

如果数值不一致，不要继续使用这份副本，应回到发布页面重新检查并下载。也不要通过重命名，把一种架构的软件伪装成另一种架构；文件名变化不会改变程序内容。对于不熟悉命令行的用户，可以先理解校验的用途，再使用自己熟悉的本地校验工具。

<h2 id="windows">在 Windows 上安装 DeckCraft</h2>

先查看电脑是 Intel/AMD 64 位处理器，还是 ARM 架构处理器。上游文件命名中的 `windows-x64` 和 `windows-arm64` 分别对应不同构建。某些版本还会提供其他选项，具体以你选择的发布页为准。[上游 Windows 下载说明](https://github.com/storytold/deckcraft#windows)提供包类型信息。

### 使用安装器

下载匹配的 `.msi` 文件，等待下载完成后从保存目录打开。阅读安装提示；没有特殊要求时采用常规安装位置即可。安装完成后，先运行新建测试文稿，不要立刻把重要文件的唯一副本交给新环境处理。

如果 Windows 出现提示，核对来源、文件名和发布者信息。提示出现时应该先理解原因，而不是照搬关闭全局保护的教程。公司设备可能受到管理员策略限制；换一种安装包格式并不意味着可以绕过组织的软件政策。

### 使用便携版

下载对应的 portable ZIP，完整解压到单独文件夹，然后从解压后的目录启动。不要直接在压缩包预览窗口里运行，也不要只复制一个可执行文件而丢弃配套文件。

建议选择稳定的位置，而不是经常清理的临时目录。需要快捷方式时可以单独创建，但演示文稿应放在自己的项目文件夹中。把应用程序和文稿分开，后续替换便携版或删除旧程序时更不容易误处理作品。

<h2 id="mac">在 macOS 上安装 DeckCraft</h2>

从发布附件选择 macOS 应用的 DMG。上游列出了同时面向 Apple silicon 与 Intel 的 universal 应用包。命令行 ZIP 用于终端工作流，和图形界面应用不是同一个下载项目。可参考[macOS 包说明](https://github.com/storytold/deckcraft#macos)。

打开下载的磁盘映像，按其中的说明安装，通常是把应用复制到 Applications，然后运行安装后的副本。确认可以打开后，弹出挂载的磁盘映像，避免以后一直运行临时挂载位置里的程序。

如果系统阻止启动，认真阅读实际提示。下载未完成、系统不兼容、设备管理限制和普通首次打开确认，需要不同处理。检查当前发布说明与系统设置，不建议使用一条宽泛命令移除所有应用的安全限制。

首次测试放在容易找到的文件夹里进行：创建一个小文稿，保存后再退出，随后重新打开。这样同时检查应用启动和文件流程。仅仅看到主窗口出现，还不能证明关闭应用后能恢复自己的工作。

<h2 id="linux">为 Linux 环境选择合适的包</h2>

Linux 用户既需要确认架构，也需要确认发行版。发布附件可能提供多种格式，不同版本的选项也可能变化。应结合附件列表和[上游 Linux 文档](https://github.com/storytold/deckcraft#linux)判断，而不是只看后缀是否熟悉。ARM 设备不能因为使用 Ubuntu，就直接安装 x86_64 包。

Debian 或 Ubuntu 通常从 `.deb` 开始；RPM 系发行版则优先查看对应 `.rpm`。包管理工具往往能够更清楚地提示依赖情况。确认安装前，阅读拟执行的变更，尤其是在同时承担其他工作的电脑上。

AppImage 适合评估独立包工作流。把文件保存在固定目录，必要时只为这个文件授予执行权限，然后运行。假设下载文件名为 `downloaded-deckcraft.AppImage`，基本命令如下：

```bash
chmod +x ./downloaded-deckcraft.AppImage
./downloaded-deckcraft.AppImage
```

这些命令不会自动补齐系统库，也不会解决架构错误。如果终端报告错误，保留原始信息，按照当前发行版与发布文档查找原因，不要直接复制另一种发行版的一长串安装命令。

无桌面服务器、远程会话、虚拟机和精简桌面环境，可能与普通桌面具有不同的图形和文件对话框支持。成功下载不等于能够运行图形界面。应在最终打算使用的桌面会话中测试，并留意是否有图形驱动、运行库或文件选择器方面的具体错误。

<h2 id="first-run">完成一次五分钟的首次启动检查</h2>

用不含敏感信息的临时文稿进行测试。目标是在截止日期之前发现基础问题，测试规模要足够小，方便每次更新后重复：

1. 打开空白或示例文稿，在两页之间切换。
2. 输入短标题，添加一个图形，并修改一项格式属性。
3. 保存到已知目录，使用容易识别的文件名。
4. 重新打开保存的副本，确认文字和图形仍然存在。
5. 进入演示模式，检查翻页，再返回编辑。

如果需要交换 PPTX，再加一项：在接收者实际使用的软件中打开保存结果。检查排版，而不只是检查是否能打开。已有 PowerPoint 文稿也应使用副本做反向测试，在验证之前保留原件。

<h2 id="updates">更新时保留工作成果和版本线索</h2>

替换安装之前，保存所有打开的文稿，并备份重要文件。阅读新版本说明，重新确认系统和架构。更新可能改善某个流程，也可能改变另一个流程，所以更新后仍应重复前面的保存与重新打开测试。

便携版可以先解压到一个新目录，保留旧包供对照。不要把一个版本的程序与另一个版本的配套文件混在一起。安装器则按项目说明和系统正常升级流程处理。

除非更新能解决阻止交付的问题，而且有时间重新测试，否则不建议在演示前临时升级。已经排练过的环境，比刚下载、尚未验证的新环境更有参考价值。重要场合准备一份静态副本或另一条已测试的演示路径。

<h2 id="troubleshooting">根据实际症状排查安装问题</h2>

### 下载文件无法打开

检查后缀、下载完成状态，以及它是不是图形应用包。核对系统和架构；压缩包应完整解压，源代码包不会像安装器一样运行。

### 应用启动后立刻退出

先不打开现有文稿，只启动应用。如果仍然退出，记录版本、系统和错误输出。上游提供[日志说明](https://github.com/storytold/deckcraft#logs)和平台相关排错信息，修改渲染设置之前应阅读当前文档。

### 文稿字体缺失或文字位置变化

这更像文件兼容性问题。对照可用字体和原作者软件中的显示效果，定位受影响对象。反复安装相同软件包通常不能解释是哪种字体发生了替换。可以参考[跨软件兼容性测试](/guides/deckcraft-vs-powerpoint-guide#compatibility)。

### 电脑不允许安装应用

先了解设备政策，必要时联系管理员。如果允许使用网页应用，可以评估[在线编辑器](/app)。它仍需要合适的浏览器环境，也不应被当作绕过组织文档管理要求的方法。

<h2 id="faq">常见问答</h2>

### 桌面版需要付费下载吗？

上游通过公开发布页面分发应用。应从项目下载，避免额外的第三方下载管理器。许可与附带资源说明以项目为准，本指南没有额外付费激活步骤。

### deckcraft.me 是上游官方发布者吗？

不是。本站是独立指南与在线工作区，应用源代码和发布包由上游项目维护。需要核实桌面下载来源时，应查看链接的仓库。

### 应该使用最新版还是本站测试过的版本？

结合发布信息和实际需求决定。新版本先用文稿副本测试。本站浏览器构建与快捷下载链接可能落后于上游，不要默认所有入口版本同步。

### 安装以后下一步做什么？

完成小型保存测试后，按照[第一份幻灯片指南](/guides/deckcraft-slides-guide)制作完整练习。[首页](/)集中提供编辑器、教程、下载和支持入口。
